# openPDF for macOS

Native SwiftUI + AppKit viewer. No Catalyst, no webviews.

Tiles are core RGBA (`PdfDocument.renderTile`) drawn into a `CALayer`-backed
`NSView`. The LRU cache lives in `openpdf-core`; Swift only asks for visible
and thumbnail tiles. Opening a file uses `NSOpenPanel`. A signed document
stays read-only. The PIN dialog implements the UniFFI `PinProvider` callback:
it shows `pin_prompt` plus `describe_pin_status`, and an empty field or Cancel
is `FfiError.PinCancelled` (silent, never an empty PIN).

en/es strings come from the shared `po/` catalog (`translate`) and from
`.strings` generated by `scripts/po-to-strings.py`.

## Build

macOS only. From the repo root:

```bash
export OPENPDF_PDFIUM=/path/to/libpdfium.dylib   # pdfium-mac-arm64, chromium/8035
./apps/macos/build.sh
```

`build.sh` compiles `openpdf-ffi`, generates UniFFI Swift, then `swift build`.
`xcodebuild -scheme OpenPDF -destination 'platform=macOS'` works after that
(SwiftPM package).

## Measure

Same `key=value` report as `openpdf-gtk --measure`:

```bash
./apps/macos/.build/release/openpdf-macos --measure 32
```

Gates: startup ≤ 8000 ms, peak RSS ≤ 250 MiB (`ru_maxrss` is bytes on macOS),
at least 1 visible tile and 3 thumbnail tiles. Hidden `NSWindow` (no GUI
required beyond a window server). Exit 0 if `ok=true`.

Timing marks (milliseconds from process start, same keys as `openpdf-gtk`):
`ui_activate_ms`, `ui_window_present_ms`, `ui_first_frame_ms`,
`ui_first_tile_ms`, `ui_adw_init_ms` (AppKit bootstrap), `ui_css_ms` (unused),
`ui_window_build_ms`, `ui_doc_load_start_ms`, `ui_doc_loaded_ms`,
`ui_first_tile_requested_ms`, `ui_first_tile_rendered_ms`,
`ui_first_texture_uploaded_ms`. The window is presented before PDFium/tile work.
